# 安装、升级与恢复

本指南适用于 **Redmi AX6000 / RB06，普通 110m 布局**。本仓库三个系列均只发布这一布局的固件，小米 AX6000 / RA72 不是同一设备。

切换系列前先确认常用插件的兼容性：25.12 使用 FW4 / APK，24.10 使用 FW4 / IPK，21.02 使用 FW3 / IPK。不同包格式不能混装，相同包格式也需匹配系统、防火墙和依赖。

先确认当前设备属于哪种情况：

- 已安装本仓库 21.02、24.10 或 25.12 普通 110m 固件，且管理页面可用：优先按[网页升级步骤](#web-upgrade)更新或回退；跨系列切换时取消保留配置，目标镜像须通过兼容性检查。
- 仍在使用小米原厂系统：按[首次安装](#原厂首次安装)准备，不能套用系统网页升级步骤。
- 系统无法启动：先确认[引导恢复入口](#u-boot-恢复与布局边界)是否可用，再选择匹配布局的镜像。

<a id="layout-comparison"></a>

## 安装前确认普通 110m 布局

普通 110m 在发行说明中标记为 `immortalwrt-110m`，ZIP 文件名中简写为 `110m`。它将系统区域统一分配给内核、系统文件及用户数据，使剩余空间更便于用于插件和数据。

**110 MiB 不等于刷机后有 110 MiB 可用。** 内核、系统文件、闪存管理和坏块预留都会占用空间，实际余量以启动后的显示为准。

<a id="按当前设备状态选择"></a>

本仓库不发布 stock 或 `ubootmod` 固件。使用这些布局或小米原厂系统的设备，不能直接按本文的网页升级步骤刷入普通 110m 镜像；须先按适用的安装方案处理分区和引导。**上传固件不会自动完成布局转换。** 不清楚当前布局时，先确认分区与引导信息，再决定安装方式。

<a id="verify-download"></a>

## 先核对固件和备份

1. 在发行说明中核对型号、布局、系统与无线版本、预装功能和默认地址。
2. 下载该版本的固件 ZIP，核对完整 SHA-256 后解压，再用包内 `SHA256SUMS` 校验要刷写的镜像。
3. 把配置备份、上网参数、独立插件的数据与安装包保存到电脑，同时保存一份在本机可用、布局匹配的旧固件。取消保留配置会清空原网络、Wi-Fi 和管理密码等设置，先记下重新配置所需的信息。
4. 首次安装或涉及恢复时，备份这台设备自己的 BL2、Nvram、Bdata、Factory、FIP 及分区记录；如果还需要回到小米原厂系统，须一并保存原厂系统分区。至少留两份独立副本。Factory 分区含本机无线校准信息，与下载包里的 `factory.bin` 系统镜像不同，不能用其他设备的备份替代。
5. 使用有线连接和稳定电源，记下当前地址、目标默认地址及已有引导的恢复方式。

### ZIP 内使用哪个文件

| 文件 | 用途 |
|---|---|
| `firmware/*squashfs-sysupgrade.bin` | 在系统内更新或回退，必须匹配设备和当前布局 |
| `firmware/*squashfs-factory.bin` | 配套 U-Boot 网页的安装或恢复镜像，无需与 sysupgrade 依次刷入 |
| `bootloader/mt7986_redmi_ax6000-fip-fixed-parts.bin` | 三个系列的新发行包均附带的 RB06 普通 110m 引导文件，初次安装或明确需要更新引导时使用；日常系统升级无需重刷 |
| `release-notes.md` | 该版本的系统、内核、默认设置和插件说明 |
| `packages.txt` | 实际预装软件包及版本 |
| `SHA256SUMS` | 包内文件的 SHA-256 校验清单 |

**GitHub 自动生成的 Source code 压缩包不能刷机。** 使用旧发行包时，先核对其实际文件清单；缺少 factory 或引导文件时，先准备匹配设备和布局的恢复包。FIP 是引导文件，不能上传到 LuCI 系统升级页面。

在文件所在目录执行，文件名替换为实际下载的 ZIP 或解压后的镜像：

```powershell
Get-FileHash -Algorithm SHA256 .\实际文件名.zip
```

Linux 使用 `sha256sum 实际文件名.zip`，macOS 使用 `shasum -a 256 实际文件名.zip`。将完整结果与发行说明或 GitHub 附件的 `sha256:` 摘要比较；镜像则与同包 `SHA256SUMS` 比较，不只核对前几位。

<a id="web-upgrade"></a>

## 从系统网页更新或回退

当前运行本仓库普通 110m 固件、管理页面可正常登录时，使用此流程更新或回退，无需进入 U-Boot 或重刷 FIP。目标镜像必须通过设备和布局检查；此流程不转换分区。旧版页面拒绝目标镜像时，按[配置保护与旧版处理](#配置与插件怎么恢复)操作。

| 操作 | 固件与配置选择 |
|---|---|
| 同一系列内更新 | 普通 110m 的 `sysupgrade.bin`；版本说明允许时，可按需保留配置 |
| 在 21.02、24.10、25.12 之间升级或回退 | 两侧均为普通 110m，使用目标系列的 sysupgrade，取消保留配置；重新安装匹配的 IPK 或 APK 插件 |
| 回退同一系列内的旧版 | 普通 110m 旧镜像，建议取消保留配置，再重新设置或恢复匹配备份 |

1. 完成前述备份和校验，登录当前系统的“系统 → 备份/升级”。
2. 上传解压后的 `*squashfs-sysupgrade.bin`，不要上传整个 ZIP、factory 或 FIP。
3. 核对设备识别和兼容性结果。提示不兼容时停止刷写，重新核对设备和镜像，不强制跳过检查。**跨 21.02、24.10、25.12 系列时取消“保留配置”及其他保留设置的选项。**
4. 确认后保持供电和有线连接，等待写入、重启，勿因管理页面断开而中途断电。
5. 未保留配置时，让电脑重新获取地址，以目标默认地址登录，重新设置密码、WAN、LAN 和 Wi-Fi；保留配置时沿用原地址与设置。
6. 检查 WAN、DNS、双频 Wi-Fi、IPv6 和重启后的状态，再安装匹配的独立插件并恢复必要数据。

升级后若仍显示旧版页面、版本文字或样式，先按 `Ctrl+F5` 强制刷新；仍未更新时，清除路由器管理地址的站点缓存，再重新登录。仅处理浏览器显示问题，无需恢复路由器出厂设置。

熟悉命令行的用户也可使用系统内的 SSH sysupgrade。系统无法启动或管理入口不可用时，按下文 U-Boot 恢复流程处理。

## 配置与插件怎么恢复

| 操作方式 | 设置与外装程序 |
|---|---|
| 同系列且配置兼容，LuCI 选择保留配置，或 SSH sysupgrade 未指定 `-n` | 保留实际备份清单中的设置和管理密码；外装程序需要另行准备 |
| LuCI 取消保留配置，或 SSH sysupgrade 使用 `-n` | 清空原运行配置，按新系统重新设置 |
| 配套 hanwckf U-Boot 网页安装 factory | 按重新安装处理，原配置、密码与外装程序不会自动保留 |

**在 21.02、24.10、25.12 之间切换时，升级和回退都取消保留配置。** 三个系列的防火墙、网络和软件包存在差异，25.12 的有线端口还采用 DSA。完整备份仅用于恢复对应系统；不要整包导入另一系列，也不要直接覆盖其无线配置、防火墙规则、启动脚本或内核模块。

升级页面的配置保护会在跨系列或配置不兼容时取消“保留配置”，并提示清空密码、网络等设置；同系列且兼容时仍可自行选择。刷写前确认最终选项，清空设置后按目标默认地址重新配置。

**旧版升级页面的处理：** 自动保护由当前运行的系统提供。如果没有自动提示，跨系列时手动取消保留配置；仍无法通过检查时，改用下文的 U-Boot factory 恢复流程，不勾选强制升级。

**保留配置不等于保留外装插件。** 升级前另存插件安装包、配置、数据库和订阅，并检查系统备份中实际包含哪些文件。升级后安装适用于目标系统及其防火墙版本的软件包，再恢复需要的数据。备份可能含密码等信息，请保存在自己的电脑上。

先确认基础上网和 Wi-Fi，再恢复代理及其他服务。出现问题时按[反馈说明](../README.md#反馈)记录；管理页面仍可用时，可从同一入口回退匹配布局的旧镜像，再恢复该系统对应的备份。

## 安装与更新软件包

进入 **系统 → 软件包**，可从软件源安装，或使用上传入口安装本机文件。25.12 选择 `.apk`，24.10 / 21.02 选择 `.ipk`；不要通过改扩展名转换格式。安装前确认系统系列、CPU 架构和依赖相符，内核模块还必须匹配本固件的内核版本与 ABI。

### 25.12 手动上传 APK

1. 上传 APK，核对确认框中的文件名和大小；有发布方提供的摘要时一并核对。
2. 按需选择以下单次选项。通常保持默认、不勾选即可。
3. 点击安装并等待结果，再到已安装列表和插件页面确认版本与运行情况。

| 选项 | 何时使用 | 注意事项 |
|---|---|---|
| 允许安装未受信任的 APK（跳过签名验证） | 已确认来源，但软件包未由系统信任的密钥签名时 | 对应 `--allow-untrusted`；只用于可信来源，不会绕过架构、版本或依赖检查 |
| 不联网安装（APK --no-network） | 希望软件包工具仅使用已安装或本地可用的依赖时 | **缺少依赖会安装失败**；只禁止 APK 工具下载，不保证插件安装脚本不会联网 |

两个选项互相独立，仅用于本次上传安装；后续安装不会自动沿用。较早版本没有这些选项时，请按其页面和发行说明操作。

| 页面结果 | 下一步 |
|---|---|
| 安装成功 | 软件包命令已完成；仍需到插件页面配置并确认服务可用 |
| 安装失败 | 查看命令输出中的原因；部分文件或依赖可能已发生变更，处理原因后再重试 |
| 无法确认安装结果 | 网络中断或页面未取得完整结果；先查看已安装列表和版本，避免立即重复安装 |

补充日志中出现警告，不一定代表安装失败，应结合页面结果和已安装列表判断。

25.12 网页上传的 APK 暂存在内存目录 `/tmp`，安装命令结束后会清理，取消安装也会删除该次上传。上传后直接关闭页面或意外中断时，临时文件可能暂留至重启。**安装后的程序和插件数据仍会占用可写闪存**，不能用安装包的压缩大小推算实际占用；查看剩余空间请以系统显示的可用空间为准。

<a id="backup-space"></a>

### 保留配置后的空间占用

25.12 在保留配置升级时，会跳过未改动且与系统内置版本一致的部分 OpenClash 数据库，例如 `Country.mmdb`、`GeoSite.dat`，减少同一份内置数据重复写入可写分区。修改过的数据库、个人配置、订阅、规则和代理核心仍按备份规则处理；这项优化不会清理当前运行系统中的文件。

备份由**升级前正在运行的系统**生成。从不具备该功能的旧版首次升级时，数据库副本仍可能随备份恢复；新固件不会自动删除它们。升级前先将配置备份下载到电脑，再检查页面是否提供“跳过与 `/rom` 相同的文件”选项。

该选项的范围比 OpenClash 数据库去重更广，会影响全部与内置内容相同的备份文件。如果修改过文件权限、属主或链接关系，或无法确认这些改动是否需要保留，不要仅为节省空间勾选。不要恢复旧的完整备份后又期待副本自动消失，也不要直接删除已挂载的 `/overlay/upper` 文件。

升级后的可用空间还受外装插件、数据库更新及闪存压缩影响，以重启后的实际显示为准。

## 原厂首次安装

首次安装需要取得管理权限、备份本机分区、确认引导与布局、安装系统并完成初始设置。原厂版本会影响取得权限的方法，不能套用普通 LuCI 升级步骤。

选择所需系列的发行包，准备其中的 `bootloader/` 配套 FIP 和 factory 镜像，无需先装 21.02。完成设备解锁、本机分区备份和布局核对后，再安装匹配引导及系统镜像。

引导及操作依据见 [hanwckf/bl-mt798x](https://github.com/hanwckf/bl-mt798x) 和 [hanwckf 的 U-Boot 使用说明](https://cmi.hanwckf.top/p/mt798x-uboot-usage/)。FIP 与系统镜像分别使用对应入口；FIP 不能上传到 LuCI 系统升级页面，也不要把这里的 sysupgrade / factory 文件直接上传到小米原厂网页。已经使用匹配普通 110m 引导的设备，日常更新或切换系统无需重新刷写 FIP。

## U-Boot 恢复与布局边界

系统无法启动但引导仍可用时，使用匹配设备与普通 110m 布局的 `*squashfs-factory.bin` 重新安装。以下进入方式适用于配套 hanwckf U-Boot 的默认设置；改过恢复地址或按键的设备，以其引导配置为准。恢复页地址与系统 LAN 地址是两套设置。

1. 关闭路由器电源。电脑用网线连接 LAN，临时将有线网卡 IPv4 设置为 `192.168.31.100`、子网掩码 `255.255.255.0`。
2. 按住路由器 RESET 按钮后通电，保持至少 15 秒再松开。
3. 用浏览器隐身窗口打开 `http://192.168.31.1`。如果未出现引导页面，先检查有线连接和电脑静态地址。
4. 核对下方布局说明。多布局引导选择 `immortalwrt-110m`，在**固件更新入口**上传已校验的 factory 镜像，确认后开始刷写。
5. 保持供电，等待完成并自动重启。将电脑 IPv4 恢复为自动获取，使用目标系统的默认管理地址登录，重新设置密码和网络。

进入步骤依据 [hanwckf 的引导使用说明](https://cmi.hanwckf.top/p/mt798x-uboot-usage/)。恢复系统使用 factory，无需同时更新 FIP。

多布局版 U-Boot 如果提供以下选项，含义如下。本仓库固件请选择 **`immortalwrt-110m`**：

| 页面选项 | 系统区域布局 | 本仓库固件 |
|---|---|---|
| `default` | 内核区 30 MiB 与系统区 80 MiB 分开 | 不匹配 |
| `immortalwrt-110m`（110m） | 合并为一个 110 MiB 的 UBI 区域 | 匹配 |

这里的 `default` **不表示沿用当前布局**。部分多布局页面显示的“当前布局”与下拉框初始选项不联动，每次上传前都要检查下拉框实际选中 `immortalwrt-110m`，不要仅凭当前布局文字判断。固定 110m 引导没有这个选择；其他引导版本以其说明为准。

**U-Boot 安装或恢复使用 factory 镜像，按重新安装处理，不保留原设置。** 完成后重新设置密码和网络，原数据从事先保存的匹配备份恢复。

布局变更或原厂恢复按对应引导文档处理，不属于普通系统升级；不要擦写无关的校准、身份分区，也不要使用另一台设备的备份。

引导恢复页也不可用时，停止重复试刷，保留设备状态并确认串口或其他恢复方式。
